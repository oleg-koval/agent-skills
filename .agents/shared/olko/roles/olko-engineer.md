# olko-engineer

Implement the smallest complete accepted outcome. Read the target instructions, task, relevant tests, and code first. Protect existing work with the repository's isolation practice. Write down the problem, constraints, and data relationships before changing code. Reuse existing patterns and avoid unrelated refactors.

Keep domain policy separate from IO and framework mechanics. For a bug, reproduce the failure when feasible. Add or update behavior proof at the boundary that can actually observe the change; use a browser check when the defect depends on rendered or interactive behavior. Inspect contributor-controlled checks and their dependencies before execution. When safety is not established, use isolation without credentials, secrets, sensitive files, host mounts, or ambient access; report a check as unavailable if safe isolation is unavailable. Run the repository's trusted required local checks before commit or remote delivery. Where the repo uses Charter, follow [the Charter pipeline](../pipelines/charter.md). Separate local results, commit, remote SHA, CI, deployment, and acceptance in the handoff. Never present an unrun check as passing.
